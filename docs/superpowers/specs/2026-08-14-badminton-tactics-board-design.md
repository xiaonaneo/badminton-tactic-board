# 羽毛球战术板设计规格

## 目标

建立一个桌面端优先、纯前端运行的羽毛球战术板首版，用于在标准场地图上布置球员、记录球路并在浏览器中保存战术草稿。

## 范围

- 支持单打与双打场地线切换。
- 支持添加、删除和拖动球员标记。
- 支持绘制球路箭头与落点标记。
- 支持新建、清空、导出 JSON、导入 JSON。
- 使用 `localStorage` 持久化当前战术。
- 桌面端优先，移动端提供查看与基础拖动能力。

不包含账号、后端、多人协作、实时同步、视频分析和战术推荐算法。

## 技术方案

使用 Vite、React 和 TypeScript。应用状态集中在前端内存中，通过一个明确的序列化模型写入 `localStorage`；导入导出复用同一模型和校验逻辑。场地使用 CSS/SVG 绘制，避免引入图片资源导致缩放和坐标换算不一致。

核心模块分为：

1. 场地视图：根据单双打模式绘制场地，提供统一的相对坐标系。
2. 标记编辑器：管理球员、球路和落点的创建、移动、删除。
3. 战术存储：负责默认状态、序列化、反序列化、导入校验和 `localStorage` 读写。
4. 工具栏：提供模式切换、编辑操作和文件操作入口。

## 数据流与约束

战术状态以 JSON 兼容对象表示，所有坐标使用 0 到 1 的相对值，避免窗口尺寸变化造成数据失真。UI 操作只通过状态更新函数修改数据；存储模块不直接操作 React 组件。非法或版本不兼容的导入文件必须给出可理解的错误，并保留当前状态。

## 验收标准

1. `npm install` 和 `npm run dev` 可启动项目。
2. 用户可以在单双打之间切换，场地线显示正确。
3. 用户可以添加、移动、删除球员和球路/落点。
4. 刷新页面后，最近一次战术仍可恢复。
5. 导出的 JSON 可重新导入；非法 JSON 不会覆盖当前战术。
6. 自动化测试覆盖状态默认值、序列化往返和导入校验。

## 风险与取舍

- 首版采用相对坐标，优先保证跨尺寸稳定；不承诺像素级打印布局。
- 使用 `localStorage` 意味着数据只属于当前浏览器；导出 JSON 是跨设备迁移的主要方式。
- 移动端只保证基础操作，不为触控手势引入额外的复杂交互层。
